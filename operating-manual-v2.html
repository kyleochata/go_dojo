go-dojo // operating manual

How to actually run the plan_

The ruling defines what to practise. This manual defines how: the repository that holds it, the Claude Code sessions that power it, the exact commands you type each day, and the discipline points that quietly decide whether the whole thing works. One mental model before anything else: you are the reviewer being trained; Claude Code plays three separate characters; the git repo is the plan's memory. Every rule below exists to keep those three things from blurring into one.

01 · one-time setup — do this before week 1

Build the repository

Everything lives in one local git repo. Claude Code automatically reads CLAUDE.md at the repo root every session — that file is how the standing rules get enforced without you re-typing them, and the .claude/commands/ folder is how the three agent modes become one-word slash commands.

go-dojo/ ├── CLAUDE.md ← standing rules; loaded automatically every session ├── .claude/commands/ │ ├── tutor.md ← /tutor — explain, worked examples, quiz me │ ├── author.md ← /author — build worksheets + sealed answer keys │ ├── generator.md ← /generator — solve (downstream only) │ └── score.md ← /score — grade my work against the sealed key ├── log.md ← THE product: mistakes, rungs, spaced queue, scores ├── catalogue.md ← the Go sabotage catalogue (version-pinned) ├── real-bugs.md ← production bugs + "would drills have caught it?" ├── templates/ ← the standing template week (Sunday floor) ├── worksheets/2026-w31/ ← one folder per ISO week: mon.md … fri.md ├── sealed/2026-w31/ ← answer keys. NEVER opened before scoring. ├── src/ ← your implementations — this is what Thursday hunts └── idioms/ ← the Go idiom deck, one file per snippet

Step 1 — create it

$ mkdir go-dojo && cd go-dojo && git init $ mkdir -p .claude/commands templates worksheets sealed src idioms $ touch CLAUDE.md log.md catalogue.md real-bugs.md $ go version # record this in catalogue.md — the version pin

Step 2 — write CLAUDE.md

This is the constitution. Every Claude Code session in this repo obeys it without being asked. Paste this (edit freely, but keep the sealed-file and downstream rules verbatim):

# go-dojo — standing rules for all sessions This repo is a deliberate-practice system. The human is training REVIEW JUDGMENT of agent-generated Go. Your job is to make them better at catching your mistakes — never to make things easy. ## Hard rules 1. SEALED FILES: anything in sealed/ is an answer key. Never print, summarize, quote, or reference its contents unless the human runs /score. If asked casually, refuse and remind them why. 2. DOWNSTREAM ONLY: never provide a solution, fix, or implementation for the current exercise until the human has shown their own attempt, written hypothesis, spec, or written explanation first. If they ask early, ask for their attempt instead. 3. NO GRADE INFLATION: when scoring, be strict and cite the rubric line for every point. A generous grade is a failed drill. 4. SABOTAGE VARIANTS: when authoring bug-hunt variants, vary defect placement, naming, and surrounding style every time; hide defects in visually boring positions (error handling, cleanup paths), not at the point of interest. Draw the defect category from catalogue.md weighted toward recent units WITHOUT announcing which category was drawn. Prefer real-bugs.md over catalogue.md as it grows. 5. VERSION PIN: catalogue entries must reproduce on the Go version recorded at the top of catalogue.md. Flag any that no longer do. 6. LOG DISCIPLINE: after any scored activity, append one line to log.md in the existing format. Never rewrite history in log.md.

Step 3 — write the three mode commands

Each file in .claude/commands/ becomes a slash command; $ARGUMENTS is whatever you type after it. Three examples — score.md follows the same shape:

# .claude/commands/tutor.md You are in TUTOR mode. Explain, give canonical worked examples, and quiz me with retrieval questions. Never do my current exercise for me. Topic: $ARGUMENTS # .claude/commands/author.md You are in AUTHOR mode. Author the requested worksheet(s) into worksheets/<current-week>/ following templates/ as the format. Write every solution and rubric to sealed/<current-week>/ — I must not see them. Confirm only WHICH files you wrote, never their contents. Task: $ARGUMENTS # .claude/commands/generator.md You are in GENERATOR mode. I will first paste my own attempt, hypothesis, spec, or written explanation. Only after that, produce your solution so I can compare. If I haven't shown mine, refuse. Task: $ARGUMENTS

Step 4 — author the foundation artifacts (~90 min, once)

Four artifacts, none of which exist yet. Each one comes from exactly one of two places: copy-paste out of the ruling document, or Claude Code writes it for you. Nothing here is invented from thin air — if you're ever unsure where something comes from, that's the answer.

Do this first: drop a copy of go-native-plan-final.md (the audited ruling) into the repo root. Claude Code can then read the spec directly, which every prompt below relies on.
$ cp ~/Downloads/go-native-plan-final.md ./ $ go version # note the output — you need it in a moment
4a · catalogue.md — copy from the ruling, then have Claude verify it

Open the ruling and find the section titled "The sabotage catalogue" — the five defect categories (memory and value semantics; maps and nil; errors; concurrency; resources). That text is the catalogue. Paste it into catalogue.md and add a version pin as the first line:

# Go sabotage catalogue Pinned to: go1.24.x (update + re-verify whenever you upgrade) ## Memory and value semantics - slice aliasing after append on a shared backing array - ... (paste the rest from the ruling)

Then verify it against your actual toolchain — this is what stops you drilling folklore like the pre-1.22 loop-variable gotcha:

> Read catalogue.md. For each entry, write a minimal Go program that demonstrates the defect, run it on this toolchain, and tell me if any entry no longer reproduces on this Go version. Flag stale ones.
4b · templates/ — Claude generates it; this is your Sunday insurance

The template week doesn't exist anywhere — /author creates it. These are the reusable default sheets that run on any week where Sunday prep doesn't happen.

> /author Build the standing template week into templates/: mon.md (laddered build sheet, primitive left blank), tue.md (idiom deck + one pattern slot), wed.md (foundations unit with a pre-test section), thu.md (bug hunt sheet with a verdict table for up to 5 variants), fri.md (the four-part explain-before-accept frame, error paths as section 2). Each sheet includes its written 10-minute floor version at the bottom.
4c · idioms/ — the ruling names the contents, Claude writes the files

Topic 7 of the ruling lists all eight snippets: container/heap, a set via map[T]struct{}, sort.Slice with a comparator, a BFS queue on a slice, two pointers, a stack, strings.Builder, and binary search on an answer space.

> /author Create idioms/ with one file per snippet from the idiom deck list in go-native-plan-final.md. Each file: the canonical minimal Go version at top, then a blank "type it cold" section, then 2-3 recall prompts.
4d · log.md — you write this one, right now, by hand

Just headers. Paste this in and it's done — it fills up one line at a time over twelve weeks.

# go-dojo log ## Sessions | date | day | topic | rung/score | notes (what went wrong, what I'd do differently) | ## Spaced re-attempt queue | item | last attempt | due | result | ## Rung state | primitive | current rung | clean runs | ## Tokens | week | tokens spent | on what | did the unit close? | ## Real-bug verdicts | date | bug | would this week's drills have caught it? (y/n/partial) | why | ## Adherence (fortnightly, 7-of-10) | fortnight | sessions started | floors used | pass? | ## Parking lot (plan-change ideas — do not act until a gate review)
$ git add -A && git commit -m "day 0: operational"
◆
The pattern that applies all twelve weeks: the ruling is the spec, Claude Code is the builder, you are the client who never accepts without reading. Any time this manual says "author X" and you don't know where X comes from, the prompt shape is always the same — point Claude at the relevant section of the ruling and name the file it should write. Day 0 is your first rep of the exact relationship the whole plan trains.
02 · the three characters

One agent, three modes, never mixed

The single most important operational habit: fresh session per mode. Run /clear (or start a new claude session) when switching roles, so the Generator has never seen the Author's answer key and the scorer isn't grading its own work with parental pride.

/tutor

Explanations, canonical worked examples, quizzing. Use freely, any time, upstream of your work.

Boundary: teaches the concept, never touches the current exercise.

/author

Builds worksheets, specs, rubrics, sabotage variants, flash cards. Runs Sunday, mostly.

Boundary: every answer goes to sealed/ — you see filenames, never contents.

/generator

Solves, implements, fixes — for comparison against your finished attempt.

Boundary: downstream only. No attempt shown, no solution given.
Why the ceremony matters: your documented failure mode is accepting agent output when uncertain. Every one of these boundaries is a wall between "Claude helps me learn" and "Claude does it and I nod." The friction is not overhead — the friction is the curriculum.
03 · the weekly loop

Click a day for its playbook

The week is a pipeline: Sunday manufactures it, Monday–Wednesday build skill, Thursday attacks what you built 1–2 weeks ago, Friday drills the supervision habit itself. Each card below opens a minute-by-minute playbook with the actual commands.

⚠
Bad week? Run four days and skip the drop day — Tuesday during weeks 3–5, Wednesday from week 6. That is the buffer working as designed, not falling behind. Never "make it up."

04 · the day job — where the plan actually pays out

The standing rule at work

The worksheets are the gym; the job is the sport. Every agent-generated diff, in any language, at work or in practice, hits this gate:

Full four-part written treatment if the diff is over 80 lines, or touches goroutines, channels, mutexes, context propagation, or error handling at any size. Everything smaller: section 4 only — "the one line most likely to be wrong, and why." Keep a scratch file or a sticky note with this threshold where you review; an undefined threshold defaults to never, and so does a forgotten one.

And the loop that keeps the whole system honest: when a real bug reaches review or production, within 24 hours append to real-bugs.md — what it was, and the verdict: would this week's drills have caught it? Three consecutive "no"s means the sabotage bank has drifted from reality; rebuild it from the real-bug list. This is the only place reality grades your curriculum. Don't skip it because the bug was embarrassing — embarrassing bugs are the syllabus.

05 · field notes — the things you'll forget by week 3

Discipline points and quiet traps

01

The sealed folder is the whole game

Every drill's value comes from you committing to an answer before seeing the key. One casual cat sealed/… converts a drill into reading. CLAUDE.md tells Claude to refuse; help it help you — never tab-complete into that folder, and consider chmod 000 sealed/2026-w32 until Sunday if you don't trust Friday-night you.

02

Fresh context per mode, always

/clear between roles. A Generator that watched Author build the answer key isn't generating — it's leaking. A scorer grading in the same session that produced your hints will grade warmly. New session, paste only what the role needs.

03

Feeling fluent is not the same as learning

The sessions that feel smooth — reading Tutor explanations, watching Generator solve — produce the least retention. The ones that feel awful — cold pre-tests, rung-3 blanks, hunt verdicts you're unsure of — produce the most. Desirable difficulty is the plan working. If a week felt easy, suspect it.

04

Suspicion is not detection

Around week 4 you'll be tempted to call everything defective — it feels rigorous. It isn't: false positives are scored as errors because a reviewer who flags everything is as useless as one who flags nothing. The skill is calibration, and "this is clean, and here's why I'm confident" is the harder verdict.

05

The log is the product; worksheets are disposable

Twelve weeks from now the worksheets are landfill and log.md is the asset — it drives spaced re-attempts, rung state, gate evidence, and the week-12 audit. Sixty seconds per session, one line, never skipped, never rewritten. When in doubt what to log: what you got wrong and what you'd do differently.

06

Keep permission prompts ON for drills

Claude Code's auto-accept modes are great for real work and poison here — the entire plan exists because accepting without reading is your habit. In this repo, run interactive, read every proposed edit, and treat each accept prompt as a free rep of the exact skill being trained.

07

Don't tune the plan mid-phase

By week 5 you'll have ideas for improving the rotation. Write them in the log's parking lot and change nothing until a gate review. Fiddling with the system is the most respectable-looking form of quitting it — four panels already argued this; your job is contact with Monday.

08

The restart rule, verbatim

After any break: resume at the current rotation day (never "catch up"), flash deck only for two days, no spaced re-attempts in week one back. Missed sessions are gone and owed to no one. Adherence is 7-of-10 per fortnight — there are no streaks to break, by design, because streak-guilt kills plans like this.

09

Tokens are decisions, not drift

An overtime token is spent by saying out loud "I'm spending a token" and setting a new 30-minute timer — LEARN only, two per week, non-rolling. Blowing 20 minutes past the bell without deciding is not a token; it's the timer dying. And a unit that burns a token without closing is mis-scoped: split it, log it, no second token that week.

10

Commit messages are infrastructure

mon: rate-limiter rung2 clean 2/2 → advance costs five seconds and is exactly how Sunday's Author finds 7–14-day-old hunt targets and how the week-12 audit reconstructs your trajectory. Lazy commit messages quietly break Thursday.

11

Watch for the agent's tells

If Thursday starts feeling easy, check why you're catching bugs. "The variable's named tmp and Author always does that" is learning the agent, not Go. Log the tell, tell Author to break the habit, and let real-bugs.md keep displacing the synthetic catalogue — production doesn't have tells.

12

Sunday is sacred; the floor is the fallback, not the default

The 10-minute floor exists so a bad Sunday can't stall the week — but if you run the floor two Sundays straight, that's a signal, not a lifestyle. Log it in the adherence tally and treat the third Sunday as non-negotiable. The template week keeps you moving; only real prep keeps you progressing.

⚠
The one metric that predicts everything: sessions started. Not sessions perfected, not rungs cleared — started. Every rule above (floors, no streaks, drop day, restart protocol) exists to protect that number. When in doubt, open the sheet and start the timer; the plan handles the rest.
06 · your first seven days

Bootstrapping order

Day 0 (any day) — build the repo · ~90 min, once

Sections 01 above, top to bottom: repo, CLAUDE.md, the four commands, catalogue (version-verified), template week, idiom deck, log headers. Also write the work threshold note and put it where you review diffs. Commit everything.

First Sunday — author week 1

Run the full Sunday playbook. Week 1 specifics: Monday enters the ladder at the lowest rung you can't do cold (expect rung 1–2 — that's correct, not embarrassing); Wednesday is Big-O week 1; Thursday has no 7-day-old code yet, so Author seeds the hunt from small programs it writes fresh — from week 3 onward it's your aged code, forever.

Week 1 — run it deliberately slow

The goal of week 1 is not skill, it's installing the loop: timer on, attempt first, sealed folder untouched, log line, commit. Expect every session to run awkward and slightly over. That's setup cost, not a verdict on the plan. By week 3 the mechanics are invisible and the content is all that's left.

  • Score yourself strictly on the mechanics, generously on the Go.
  • End the week with the fortnightly tally started: sessions attempted, floors used, tokens spent.
  • Then stop evaluating and just run weeks 2–12. The next scheduled judgment of this plan is the week-12 gate, against the log — not a feeling on a Tuesday.
